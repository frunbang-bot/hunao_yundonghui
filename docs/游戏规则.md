## 实体游戏基本流程

这是 CMYK 的 36 角色版 Magical Athlete。常规游戏有四场比赛，每场换一个角色，总分最高者获胜；总分相同可以并列获胜。

1. **组队**：常规模式每人获得四名不同选手。规则提供蛇形选秀，也允许初次游玩时随机发牌。
2. **派出选手**：每场开始前各自选择角色，所有人提交后同时公开；已用角色不能再上场。
3. **轮流行动**：通常掷六面骰并按点数完成主移动，再依照各角色能力处理变化。角色能力中的“可以”表示可选。
4. **结算本场**：第一名、第二名分别获得对应奖励；第二名产生时本场立即结束。
5. **下一场**：更换选手，常规赛道顺序为普通、特殊、普通、特殊。上一场最后方或最先被淘汰的选手所属玩家先行动。
6. **第四场结束**：比较累计积分，包括名次奖励和途中取得的积分。

以上流程参考 [英文规则书，第 12—21 页](https://tesera.ru/images/items/2587383/How_to_play_Magical_Athlete_compressed.pdf)。具体奖分、赛道格位和两人变体需独立确认，不能套用旧版 Magical Athlete 的数字。

## 结算术语

| 概念 | 程序必须区分的含义 |
|---|---|
| 主移动 | 本回合的常规行动；额外移动不能自动套用所有主移动加成。 |
| 骰面点数 | 最终保留的掷骰结果；与加减后的移动距离分别存储。 |
| 移动 | 从旧格到新格，记录方向、距离、来源及是否主移动。 |
| 瞬移 | 直接改变位置；不产生经过路线，但可能形成新的同格。 |
| 停留／同格 | 到达后的位置关系，不能把移动途中的短暂经过当作同格。 |
| 超过 | 移动前在对方后面，移动后在对方前面；追平不是超过。 |
| 摔倒 | 当前移动完成后，跳过下一次主移动；角色的其他触发仍可能有效。 |
| 领先／末位 | 根据仍在赛道上的有效选手计算；并列和独占分别判断。 |
| 冲线／淘汰 | 退出本场正常轮转，且不再作为普通赛道选手参与位置判断。 |

原聊天中的两处关键修正继续沿用：毒舌喷子比较的是**本回合起始位置**；挪挪只响应**其他选手**的能力。

## 需要显式处理的互动

- 一个动作可能引发多个角色反应，必须记录完整事件链，不能让不同手机各自计算。
- 同时发生时按赛道、当前行动玩家、其余玩家顺序处理；多人角色变体还需要明确同一玩家的角色顺序。
- 重掷后旧骰面不再作为最终移动骰面；重掷这个动作本身与骰面结果分开。
- 可选能力必须出现可操作的“使用／放弃”决定，不能偷偷以程序最优策略代替玩家。
- 第二名确认后立即停止剩余对局动作，避免赛后继续得分或移动。
- 无限循环不能简单依靠递归次数截断并宣布规则正确；需要记录循环现场并明确裁定。

交叉核对来源：[英文规则书文字整理](https://github.com/keai-zeng/hunao_sport/blob/master/Magical%20Athlete%20English%20Rulebook.md)。这是社区转载，出现冲突时应回查实体版。

## 36 角色裁定工作方式

每个角色在进入实现前都必须明确：触发时点、是否可选、作用对象、产生的是主移动／额外移动／瞬移还是位置修正、是否触发停格与超过事件、与冲线和淘汰的先后顺序、第二名产生后的截断方式，以及可能形成循环时的终止裁定。已有 12 个角色也纳入同一张裁定表复核，但已确认且有测试覆盖的行为不因整理工作而擅自改变。

仅在不同解释会改变比赛结果时向用户提问。提问必须给出具体局面、候选解释、各自对程序结果的影响和建议选项；用户确认后，把结论写回本文并作为后续测试依据。

## 已确认的特殊裁定

**只剩兔子无法完赛**：其他选手已经冲线，仅剩兔子会不断因独自领先跳过主移动。用户于 2026-09-23 明确要求把第二名顺位给兔子。因此程序直接递补第二名并发放本场亚军分；保留兔子的实际停留位置，日志与结算页标明递补。这是用户确认的测试规则，不声称是官方裁定。

## 首批角色的实现细节

- 先保留最终骰面，再触发跟班／尺蠖；被重掷的旧骰面不触发。
- 最终骰面为 1 且其他选手为尺蠖时，整个主移动被跳过，包括兔子加成或炼金替换距离。
- 火箭翻倍的是骰面基础值，再叠加主移动加减；黏黏怪只减一次。
- 大长腿选择固定步数时不产生骰面事件，但仍受教练与黏黏怪影响。
- 箭头产生额外移动，额外移动不再叠加主移动修正。
- 超过香蕉后完成本次移动，再标记摔倒；只是追平或从同格出发不算超过。
- 已冲线选手不再提供被动技能；产生第二名后停止后续移动与回合结束触发。
- 跟班／尺蠖可以在当前玩家移动前冲线。如果由此产生第二名，当前玩家不再移动。

这些细节已建立自动测试；它们证明程序的当前行为，不替代后续与实体版进行的完整一致性验收。
