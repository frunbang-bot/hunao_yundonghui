# 联机 MVP 设计与验收

目标：异地朋友能通过手机进入同一房间，完成多场竞速、技能决定和积分结算。先验证玩法与联机，再移植微信小程序或 App。

## 技术边界

规则引擎不依赖浏览器或微信 API。服务端拥有房间、牌组、骰子和结果的最终解释权。客户端只显示状态、提交操作，不能提交自己掷出的骰面、位置或积分。

原型由三个部分组成：独立 JavaScript 规则模块、Node 服务端、适应手机屏幕的网页界面。无需第三方安装包，Node.js 22 以上即可运行。已确认首版为 12 个角色、2—3 人；只监听本机 127.0.0.1，不发布、不提供外网连接。

## 房间与操作

- 创建房间获得随机房间码，其他玩家用房间码加入。
- 每位玩家获得独立凭证；刷新页面能恢复自己的座位。
- 未开始时允许加入，开始后锁定名单；仅房主可以开始。
- 每条操作带唯一请求编号和所见状态版本。
- 重复请求不能重复掷骰、加分或推进回合；过期操作要拒绝并同步新状态。
- 昵称仅作显示文本，不能作为身份认证，也不能作为 HTML 执行。
- 牌组选取未全部完成前，不把他人的选择发给客户端。
- 保存成功后才向客户端确认；重启恢复房间与凭证。

## 界面

房间入口、等待大厅、派出选手、赛道、当前操作、事件记录、本场结算、总成绩。用清楚的颜色与文字区分玩家，手机上操作按钮不依赖悬停。角色卡可以查看能力原文摘要。

## 开发顺序

1. 固化规则文档与参数。
2. 实现服务端房间与独立引擎。
3. 增加手机界面和对局记录。
4. 自动测试与完整对局模拟。
5. 多客户端测试及真人试玩。
6. 根据实际结果决定移植，而非仅因代码能运行就进入下一阶段。

## 验收清单

| 分类 | 必测内容 |
|---|---|
| 基本流程 | 创建／加入／开始／隐藏选牌／轮转／四场／总排名。 |
| 规则 | 每个已启用角色的正常、边界、禁用情形；主移动与骰面分离。 |
| 结算 | 同步触发顺序、冲线立即结算、淘汰、摔倒恢复、并列。 |
| 联机 | 越权、非当前玩家操作、错误凭证、重复请求、过期版本。 |
| 恢复 | 刷新、掉线后重连、服务端重启、存储失败。 |
| 隐私 | 隐藏的选择与其他玩家凭证不出现在返回数据中。 |
| 完整对局 | 不同随机种子的多场模拟；不变量及完成情况。 |
| 界面 | 手机窄屏、按钮流程、错误提示、重连提示、多人状态一致。 |

## 发布与移植门槛

测试通过表示“在当前覆盖范围内未发现失败”，不表示数学意义的零 bug。验收报告必须分别记录通过项、失败项和未验证项。

本地运行及局域网联机不等于异地联机。异地联机需要可公开访问的 HTTPS 服务；在没有实际部署和异地实测之前，不声称此项已完成。

微信登录、分享、订阅通知和原生打包属于移植阶段。只有 MVP 的范围与玩法被确认、测试通过并完成真人试玩后，才进入该阶段。
