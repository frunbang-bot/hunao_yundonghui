# 本地 MVP 验证报告

初次验证：2026-09-23；交接复核：2026-09-24。范围：12 个角色、2—3 人、四场测试规则；不代表完整 36 角色版通过验收。

## 结果

执行 `node --test`：**29 项测试全部通过，0 项失败**。其中一个测试运行了 500 局完整对局（250 局两人、250 局三人），共 2,000 场比赛，每局都到达总成绩阶段。测试使用固定种子，能够重现失败现场。运行环境 Node.js v24.19.0。

## 浏览器实测

- 创建房间，第二个独立标签页以不同昵称加入，房主端更新人数。
- 房主开赛，两端显示各自手牌；单方锁定后，另一方看不到具体选择。
- 双方选择后进入赛道，当前玩家出现掷骰按钮。
- 魔术师实际掷骰和重掷，剩余次数正确递减。
- 刷新同一标签页后，保留身份、当前骰面、剩余重掷次数。
- 主动停止本地服务后，页面显示“连接中断，正在重连”，并禁用行动按钮。
- 重启服务后可以访问首页；后台存档恢复由独立测试验证。原先的浏览器测试标签页因会话切换被关闭，因此未把“原标签页在重启后自动续玩”记为已完成的人工验证。
- 390 × 844 视口检查赛道与操作区，页面无横向溢出；角色、按钮可见。

## 已发现并处理的问题

1. 完整随机对局发现仅剩兔子会永远跳过，导致无法完成第四场。用户指定递补第二名后已修复，并增加专门回归测试。
2. 浏览器异步刷新可能收到旧于刚提交操作的状态；已添加版本比较，避免旧响应覆盖新界面状态。
3. 正在提交时离开座位可能干扰状态归属；操作期间禁用离开按钮。
4. 2026-09-29 复现 Windows 启动脚本在部分中文编码环境中于启动服务前报“命令语法不正确”。根因位于批处理文件的中文 UTF-8 提示行；启动器已改为仅使用 ASCII 命令和提示，并增加 Node 缺失与服务停止提示。

## 已知限制与待验证项

- 当前是本机多客户端原型，不是已部署的异地联机服务。
- 真机微信浏览器、微信小游戏或小程序、Android/iOS 原生运行均未验证。
- 自动完整对局已测；尚未由真人在界面完整玩完四场并给出体验反馈。
- 已准备 `docs/真人试玩清单.md`；尚待用户实际执行并反馈结果。
- 仍有 24 个角色未实现；相关复杂连锁与复制能力不在本次测试范围。
- 两人变体、蛇形选秀、托管、观战、踢人未实现。
- 并列末位的下场先手，目前采用固定座位顺序的候选规则，用户尚未回复最终选择。
- 测试赛道与奖分不是实体版精确复刻。
- 未做长时间压力测试、多进程部署、突发断电存储损坏恢复；本地 JSON 保存不替代生产数据库。
- 离开座位会清除标签页凭证；无法只凭昵称找回。页面刷新与主动离开不同。

## 移植判断

当前达到“可以本地试玩的 MVP”阶段，不能据此宣称没有任何 bug。建议先完成真人四场试玩、确认剩余裁定，再扩展角色。按用户授权边界，**不公开发布、不开始小程序／App 上线移植，分享前先处理授权**。
